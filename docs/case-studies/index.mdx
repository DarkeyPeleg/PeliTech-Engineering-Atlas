A case study is where the individual techniques have to work together, and where the trade-offs stop
being abstract.

Each one follows the same arc: requirements, both functional and non-functional; a capacity estimate
that establishes the scale being designed for; a high-level architecture and the reasoning behind
its service boundaries; data and API design; then the specific mechanisms the system needs. After
the design comes the part usually skipped — how it fails, how it is attacked, where it stops scaling,
and what was traded away to get here.

They are deliberately long. The value is in the connections between decisions, and those disappear
when a design is summarised into a diagram and a list of technologies.
