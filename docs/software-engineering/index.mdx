This section is about the part of the job that does not change when the framework does.

**Principles** covers ideas that survive across languages, and the conditions under which each one
stops being good advice. **Design patterns** are named solutions to recurring problems — useful as
vocabulary, harmful when applied as a checklist. **Clean code** is about writing for the person who
has to change this in a year. **Testing** is about building enough confidence to change things
safely, which is not the same as maximising coverage. **Debugging** is a systematic activity, not an
intuitive one. **Code quality** is what keeps a codebase workable as it grows.

The bias throughout is towards judgement over rules. Most of these ideas are correct in the
situation they were invented for and actively harmful two situations over, so each article tries to
be explicit about which situation it is talking about.
