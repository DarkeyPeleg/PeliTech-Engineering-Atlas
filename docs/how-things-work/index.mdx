Most engineers know roughly what happens when a browser loads a page, a user logs in, or a payment
goes through. Roughly is enough until something breaks in the middle.

These articles trace complete flows end to end, naming each component involved and what it is
actually doing: DNS resolution, TCP and TLS handshakes, request routing, credential verification,
token issuance, storage writes, provider callbacks. They combine explanation with sequence diagrams
and, where it clarifies something, code.

They are written to be read once for the shape of the thing and returned to when a specific stage is
misbehaving — because knowing every step in a flow is what turns "the site is slow" into a
hypothesis you can test.
