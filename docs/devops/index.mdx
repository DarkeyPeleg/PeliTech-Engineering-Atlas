Software that cannot be deployed reliably is not finished, and software nobody is watching is not in
production so much as unattended.

**Docker** covers packaging an application with its dependencies so it behaves the same everywhere.
**CI/CD** is the automation between a commit and a release, and where to put the gates. **Deployment**
covers releasing changes without downtime, and being able to undo them. **Monitoring** is about
knowing what the system is doing and being told when it stops. **Infrastructure** is the compute,
network and storage everything else assumes.

The connecting idea is feedback speed. The value of a pipeline is not that it automates work, it is
that it shortens the distance between making a mistake and finding out. Everything here is
ultimately about shortening that distance.
